# إعطاء صلاحية الإدارة وسحبها

من لوحة المدير الأساسي افتح «المديرون والصلاحيات»، أو أرسل `/admins`.

- للإضافة: اختر «إضافة مدير»، وأرسل رقم مستخدم Telegram، ثم راجع الحساب والصلاحيات واضغط التأكيد.
- للسحب: اضغط «سحب الإدارة» بجانب رقم الحساب، ثم راجع وأكد. لا يظهر زر سحب للمدير الأساسي، ولا يُسمح بإزالته من طبقة حفظ الإعدادات.
- إدارة هذه القائمة متاحة للمدير الأساسي وحده. الزبائن والشركاء والمديرون الآخرون لا يملكون منح الإدارة أو سحبها.

تتغير عضوية الإدارة في إعداد البوت وصلاحيات `commerce.support_actors`. السحب ينفذ محليًا قبل الاتصال، والإضافة تنتظر تأكيد قاعدة البيانات قبل تفعيل أدوات الإدارة. تُحفظ قائمة منع محلية حتى لا يعيد متغير بيئة قديم صلاحية حساب سُحبت إدارته. تُحدث قائمة أوامر الحساب ووضعه عند نجاح العملية، وتتوقف أزرار الإدارة القديمة بعد السحب. لا تتغير حالة شراكته أو أرصدته أو مستحقاته.

يحفظ البرنامج التغيير الموافق عليه في `.commerce/admin-role-action.json` مع صاحبه والحساب والقائمة السابقة والمطلوبة وتوقيت الموافقة والإنجاز. عند فقد الرد يبقى زر لاستكمال التغيير نفسه. تُستكمل المحاولة الموافق عليها بعد إعادة التشغيل إذا لم تتغير قائمة الإدارة، ويمكن للمالك إلغاء تغيير معلق ومزامنة القائمة الحالية. لا يعيد زر قديم تطبيق تغيير أُلغي. يرفض الحفظ مراجعة قديمة إذا تغيرت الإعدادات أثناء انتظار التأكيد.

لا تتطلب الميزة ترقية جديدة للقاعدة؛ تستخدم وظيفة `configure_support_actors` الموجودة. تحتاج إعادة تشغيل البرنامج لتحميل ملفات Python الجديدة. لم تُضف حسابات تجريبية إلى إدارة الإنتاج، ولم تُرسل رسائل تجريبية لأشخاص.

التحقق: نجح 222 اختبارًا إجمالًا، بينها 12 اختبارًا خاصًا بهذه اللوحة. أُعيد تشغيل الاختبارات الاثني عشر بعد ضبط وضع الإدارة والزبون. نجح أيضًا اختبار مع قاعدة PostgreSQL معزولة للإضافة والسحب وفقد الرد واستكماله وحماية المديرين الآخرين، دون أي سجلات مالية: [دليل الاختبار](admin_roles_acceptance_d9342e2e6eb9.json).
